## 앞으로 필요할 때 가져올 원칙

### 1. 모델 차이는 작은 프로필로 분리

출처: addon `docs/PORTING.md:3–39`.

- 공통 lifecycle·전송과 모델별 주소·모드 인코딩·capability를 분리합니다.
- 상태·오류 해석은 가능한 한 HACS 근거를 재사용합니다. 같은 모델명이나
  비슷한 MIoT 번호만으로 다른 기종 지원을 선언하지 않습니다.
- packed CLEANING_MODE·세척 주기·수분을 단순 enum 하나로 덮어쓰지 않습니다.
- 현재 필요한 수준의 프로필부터 적용하며 이전의 큰 adapter/서버 구조를
  통째로 옮기지 않습니다. 물리 동작과 기존 모델 회귀를 별도로 확인합니다.

### 2. ACK·HTTP 성공과 물리 완료를 구분

출처: lab `docs/VERIFICATION.md:15–24`, addon `docs/API.md:53–68,92–113`.

- 외부 HTTP 200과 내부 action/property code를 따로 확인합니다.
- 음수·누락·알 수 없는 값을 정상 성공으로 바꾸지 않습니다.
- 지도 요청 ACK, 실제 파일 도착, HACS decode/렌더링은 각각 검증합니다.
- timeout·취소·연결 유실 뒤 변경 명령을 새 ID로 자동 재시도하지 않습니다.
  이전 journal의 unknown을 지워 성공처럼 보이게 하지 않습니다.

### 3. HACS 패치는 원본 버전·해시를 먼저 검증

출처: lab `docs/PATCH.md:3–16,55–72`.

- 기준 upstream 버전/해시와 맞는 별도 사본에서만 패치·문법·helper를 확인합니다.
- HACS 업데이트 후 기존 패치를 무조건 다시 적용하지 않습니다.
- 기존 HA entry/entity·예약·인증·journal은 보존합니다. 구 저장소의 v2.0.3
  전용 패치를 현재 v2.0.2나 다른 버전에 그대로 복사하지 않습니다.

### 4. 지도·파일 보안은 별도 과제로 참고

출처: addon `docs/API.md:59–68`.

- 원래 설계의 단일 사용·세션 generation 결합 업로드 grant와 불변 revision
  다운로드는 향후 파일 경로 개선 때 참고할 후보입니다.
- 다른 기기의 최신 파일로 대체하거나 합성 지도로 실제 지원을 꾸미지 않습니다.
- 이것들이 현재 upstream 기반 서버에 구현됐다는 뜻은 아닙니다. 기존 내부망
  HTTP 업로드 선택을 바꾸거나 보안 기능을 자동 이식하지 않습니다.

### 5. 검증 범위를 그대로 기록

출처: lab `docs/VERIFICATION.md`, addon `docs/PORTING.md:29–45`.

- 합성 payload·loopback·운영 readback·실제 로봇 동작을 구분합니다.
- 읽기부터 확인하고 청소·복귀·세척·지도 편집 등 물리/변경 시험은 별도 승인합니다.
- 백엔드 장애를 이유로 클라우드·DNS·공유기 설정을 자동 전환하지 않습니다.

## 가져오지 않을 것

- 예전 백엔드 런타임·HACS 전송 패치·명령 journal을 현재 서버에 통째로 병합.
- 예전 TLS/인증서·계정·기기 identity·실제 지도/좌표·네트워크 주소를 공개 문서에 복사.
- 카탈로그에 주소가 있다는 이유로 모든 기능이 실기 지원된다는 주장.
- 예전 포트/slug/서버 기본값 또는 기준 버전이 다른 패치를 현재 환경에 그대로 적용.

운영 애드온과 현재 배포 helper·인증자료·복구 백업은 이 로컬 구 프로젝트 정리와
별개입니다. 향후 이식은 실제 문제가 생긴 항목의 최소 수정으로 진행합니다.
